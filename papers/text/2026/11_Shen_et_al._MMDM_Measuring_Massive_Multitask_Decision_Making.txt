Abstract
System-1 Decision Models directly make
structured probabilistic decisions over query-
specified options given a state in a single for-
ward pass, without autoregressively generating
reasoning trajectories or textual responses. Re-
cent evaluations cover diverse tasks but often
rely on existing benchmarks, where prior expo-
sure to test material can obscure generalization.
Moreover, real-world decision making often in-
volves long contexts, large option spaces, and
complex logical dependencies, challenges that
existing benchmarks do not adequately cap-
ture together. Thus, we introduce MMDM
(Massive Multitask Decision Making), a bench-
mark of 5,448 high-quality questions across 16
task categories, combining newly constructed
tasks with source-grounded recompositions and
rewrites for single-select, multi-select, and soft-
label decision making in fresh contexts. It cov-
ers realistic scenarios such as agent state track-
ing, tool and skill selection, preference judg-
ments, and rubric scoring, with option spaces

ranging from 2 to 1,024 and inputs extend-
ing to 64,817 tokens. With MMDM, we con-
duct a comprehensive quantitative evaluation
of 28 decision models, showing that many per-
form well on common knowledge yet strug-
gle with interdependent options, constrained
decisions, and multi-select tasks. For exam-
ple, Perplexity Decider-V1.2 reaches 78.75%
Hard Single-select Accuracy on world knowl-
edge, but only 53.95% on option logic and
47.95% on constraint planning, while the best
Hard Multi-select Accuracy across all models is
36.81%. These results highlight joint reasoning,
constraint-aware selection, and complete multi-
select recovery as key priorities for decision-
model development, with MMDM providing a
testbed for measuring this progress.
1 Introduction
System-1 Decision Models make structured prob-
abilistic decisions over query-specified options
given a textual state in a single forward pass (Type-
Safe AI, 2026; Microsoft, 2026), which support di-
verse applications, including text and intent classi-
fication, model and tool selection, and rubric-based
1
arXiv:2611.14309v1  [cs.LG]  10 Nov 2026

quality scoring (Ling et al., 2026). Therefore, a
rigorous and comprehensive evaluation of these
models must account for the diversity and complex-
ities of decision making in real-world scenarios.
Recent benchmarks have assessed decision mod-
els across diverse tasks and calibration crite-
ria (Duan et al., 2026; Solka, 2026; Standhartinger,
2026). However, many existing evaluations draw
heavily on widely circulated public benchmarks,
making test-set contamination a central concern for
benchmark validity (Oren et al., 2024). Moreover,
real-world decisions often combine long contexts,
large option spaces, and complex logical dependen-
cies. For example, a practically useful model needs
to track the current agent state, determine whether
an earlier approval remains valid, and select an eli-
gible tool from a large catalog with heterogeneous
prerequisites. These settings call for an evaluation
that combines task breadth with new instances and
explicit tests of these capabilities.
In this paper, we introduceMMDM(Massive
Multitask Decision Making), a benchmark of 5,448
questions for evaluating text-based System-1 Deci-
sion Models across realistic decision scenarios. It
combines broad task coverage with explicit tests of
context understanding, option discrimination, and
logical consistency. Table 1 compares its scope
with existing decision benchmarks.
Specifically, MMDM evaluatesHard Single-
select,Hard Multi-select, andSoft-labelques-
tions, requiring a unique correct choice, the com-
plete valid set, or a prediction matching the ref-
erence distribution over outcomes. These answer
types capture practical requirements such as choos-
ing the next actions, identifying all eligible tools,
and assigning probabilities to rubric scores under
uncertainty. Decisions can depend on agent states,
action prerequisites, or relationships among op-
tions. In benchmark construction, source answers
and contextual evidence ground rewrites of states,
queries and distractors to reduce memorization-
induced score inflation (Zhu et al., 2024; Zhao et al.,
2025). We combine these adaptations with recom-
positions and newly constructed tasks. The result-
ing 16 categories span knowledge and comprehen-
sion, logic and constraints, agent and workflow
decisions, and preference and rubric judgments.
With 2–1,024 options and complete inputs of up to
64,817 tokens, MMDM also tests these capabilities
across varied context lengths and option spaces.
As shown in Figure 1, our evaluation of 28 deci-
sion models reveals substantial differences across
capabilities. Models that perform well on world
knowledge still struggle with interdependent op-
tions, decisions subject to constraints, and complete
multi-select recovery. These capabilities matter in
agent workflows, where choices interact, actions
have prerequisites, and several tools or skills may
be valid for the current goal. Specifically, Perplex-
ity Decider-V1.2 (Perplexity AI, 2026) achieves
78.75% Hard Single-select accuracy on world
knowledge, compared with 53.95% on option logic
and 47.95% on constraint planning. WeMM-JEV
27B (WeMM-JEV Team, 2026) achieves the high-
est Hard Single-select accuracy of 76.00%, while
the highest Hard Multi-select accuracy is 36.81%,
highlighting the challenge of recovering all valid
options. Model rankings also differ between hard-
answer accuracy and soft-distribution error, making
both necessary to characterize decision quality.
Overall, our contributions are threefold. First,
we introduce a multitask decision benchmark that
combines fresh decision instances with long con-
texts, large option spaces, and interdependent op-
tions. Second, we provide a unified evaluation
protocol for single-select correctness, multi-select
completeness, and soft-label distributional fidelity,
together with an open dataset and toolkit. Third,
our evaluation reveals capability gaps that are not
captured by previous decision-model benchmarks,
including failures in joint consistency and complete
multi-select recovery, providing concrete directions
for future model development.
2 Related Work
System-1 Decision Models.System-1 Deci-
sion Models produce structured probabilities over
request-defined options in a single inference step.
Jev introduces a typed decision interface and Re-
inforcement Learning for Calibrated Decisions,
making probability quality a central training ob-
jective (TypeSafe AI, 2026). After this closed-
source model, open implementations explore differ-
ent ways to obtain these decisions from language-
model backbones. SemIf reads logits for option
tokens directly and supports shared-prefix reuse
across queries (Lee, 2026). OpenJev learns a
shared decision head over request-defined options,
using supervised learning followed by reinforce-
ment learning (Shen, 2026). Intern-Decision and
H2O-Lightning extend typed decisions to multi-
modal inputs (Zhu et al., 2026; H2O.ai, 2026).

mains necessary. MMDM addresses this gap by
combining fresh decision scenarios, long inputs,
and large option spaces with single-select, multi-
select, and soft-label objectives.
3 The MMDM Benchmark
MMDM evaluates decision capabilities across di-
verse tasks through a shared state–query–options
interface. First, we formalize the decision prob-
lems, answer types and evaluation objectives (Sec-
tion 3.1). Then, we describe data collection and
construction (Section 3.2). Finally, we present task
coverage and dataset statistics (Section 3.3).

3.2 Data Collection and Construction
Collection.We select public datasets and agent
trajectories that support a concrete decision with
explicit options and a checkable answer. Sources
span knowledge, reading, reasoning, preferences,
code, and agent interactions. For example, QuAL-
ITY (Pang et al., 2022) and LongBench v2 (Bai
et al., 2025) supply document-grounded questions,
BIRD (Li et al., 2023) supplies database problems,
and ComplexFuncBench (Zhong et al., 2025) and
ToolTalk (Farn and Shin, 2023) supply interaction
4

histories. Source questions and annotations provide
the basis for adaptation and verification.
Construction.We combine source-grounded
adaptation with semantic recomposition and newly
constructed tasks. For rewritten source instances,
we retain the original answers and supporting ev-
idence while reformulating the state, query, and
distractors. Semantic and option-quality checks
select the resulting instances. This strategy builds
on evidence that benchmark rewriting can mitigate
memorization-induced score inflation (Zhu et al.,
2024; Zhao et al., 2025). Recompositions introduce
decision questions grounded in source databases
or agent histories. Executable mechanisms con-
struct interacting options, constrained plans, state
transitions, and rubric outcomes with computable
answers. Across all three routes, distractors are
designed around identifiable failure modes, such
as applying an expired rule, confusing entities, or
overlooking the prerequisite.
Validation and Selection.We verify answers us-
ing source evidence, executable checks, and model
review appropriate to each construction route. Five-
model majority screening is followed by indepen-
dent human expert review of borderline cases. Both
stages apply the same quality standards for dis-
tractors, answer leakage, duplicates, and source
overlap. An option-only probe masks the state and
query; instances with unresolved shortcuts are ex-
cluded. Appendix B details the review procedure
and selection rules.
3.3 Task Coverage and Dataset Statistics
MMDM contains 5,448 questions across 16 task
categories, comprising 4,112 Hard Single-select,
633 Hard Multi-select, and 703 Soft-label ques-
tions. The 663 Score questions include 35 with
hard levels and 628 with soft targets. The collec-
tion covers 62 registered source identifiers and 80
category–subcategory combinations. Option sets
range from 2 to 1,024 options, including 94 ques-
tions with more than 255 options. Complete inputs
include the state, query, option names, and criteria.
We measure complete inputs with the Qwen3.5-
4B tokenizer from the Qwen family (Yang et al.,
2025). Their median length is 827 tokens, the 95th
percentile is 13,318, and the maximum is 64,817.
These ranges support evaluation from common
short decisions to long-document reasoning and
large-catalog selection.

4.5 Context and Option-Space Scaling
Model rankings change between long inputs and
large option sets.The two panels of Figure 4 reveal
different scaling profiles. OpenJev outperforms
Intern-Decision in every option-count bin, but falls
below it once complete inputs exceed 8K tokens.
At 8K–16K tokens, their accuracies are 15.5% and
34.5%, respectively; on 129–1,024 options, they
are 26.0% and 8.3%. This reversal distinguishes
performance on long-input workloads from perfor-
mance on large-option workloads. MMDM mea-
sures both axes because success on one does not
predict the model ordering on the other.
Large catalogs expose differences hidden by
compact choices.In Figure 4, Jev and Microsoft
Decision-1 differ by about seven percentage points
on 2–4 options, but by more than 37 points on
129–1,024 options. Perplexity retains the highest
accuracy in the largest option bin, although its ad-
vantage over Jev is much smaller there than on
9–16 options. Across the released workloads and
the protocol in Section 4.1, the curves reveal both
severe losses and changing relative advantages as
the option space grows. A single aggregate accu-
racy would conceal these differences in the scale
of decisions each model can handle.
4.6 Case Studies
Models can accept a workflow or report that con-
flicts with other evidence.In Figure 5(a), Per-
plexity V1.2 selects a workflow that approves a
document before editing it. Publication requires
approval of the final revision, so those later edits in-
validate the certificate. Jev and Microsoft Decision-
1 select a valid ordering. In Figure 5(b), Hazel’s
report is false under the unique consistent interpre-
tation, yet all three models rank it above at least
one true report. The two cases expose errors in
checking an option against history or other options,
even when the relevant conditions are explicit.
Models struggle to translate a simple record-
level defect into the correct score distribution.In
Figure 5(c), eight of nine records satisfy every
rubric criterion, while one record lacks a review
stamp. A three-record sample receives the lower
score only when it contains that record, which hap-
pens with probability one-third. However, Perplex-

lower score, while Microsoft Decision-1 predicts

5 Conclusion
We introduced MMDM, a benchmark of 5,448
questions across 16 task categories for evaluating
text-based System-1 Decision Models. With option
sets ranging from 2 to 1,024 and inputs reaching
approximately 64K tokens, MMDM tests decisions
across both familiar requests and complex contexts.
Its single-select, multi-select, and soft-label tasks
assess whether models choose correctly, identify
all valid options, and assign useful probabilities
and scores. Our evaluation of 28 decision models
reveals clear gaps between these capabilities and
exposes dimensions of decision quality that are not
captured by previous benchmarks. The strongest
models vary across answer types and task cate-
gories. High single-select accuracy can accompany
inaccurate probabilities, while deduction and rout-
ing strengths coexist with weaknesses in joint con-
straints and workflow decisions. Reliability curves
and scaling profiles further distinguish confidence
quality from accuracy and long-input performance
from large-option performance. These findings
direct progress toward checking interacting con-
ditions, handling larger decision spaces, and pro-
ducing probabilities that support reliable choices
and scores. We release MMDM and its evaluation
toolkit to make progress on these capabilities easy
to measure and compare.
Limitations
MMDM has three main limitations. First, it focuses
on text-based decisions defined by a fixed state,
query, and option set. Extending MMDM to mul-
timodal inputs and interactive trajectories would
broaden its coverage of real-world decision settings.
Second, multi-select questions are concentrated in
option logic, constraint planning, workflows, and
tool or skill selection, while most soft targets come
from rubric scoring. These settings provide clear la-
bels and verifiable target distributions, but broader
evaluation of subjective judgments will require ref-
erences that better capture variation across human
assessments. Third, MMDM combines newly con-
structed tasks with source-preserving adaptations,
recompositions, and rewrites. Although recomposi-
tions and rewrites introduce new decision require-
ments and contexts, prior exposure to the underly-
ing public source material may still occur.
Ethics Statement
MMDM combines publicly available research data
with newly constructed decision tasks. We cite the
source datasets and document their contributions
in Appendix B. Source materials remain subject to
their original terms of use. The same appendix de-
scribes model-assisted construction, label verifica-
tion, and targeted human review, including indepen-
dent assessment and adjudication of disagreements.
Our experiments evaluate model predictions from
recorded or simulated inputs; they do not execute
the tools or workflows described in the questions.
We release the benchmark and evaluation toolkit,
with source attribution, to support transparent and
reproducible research.

A Input Coverage and Task Definitions
Classification and Coverage.Table A1 defines
the 16 capabilities and links each one to its cor-
responding example in Appendix F. A category
identifies the capability a decision requires; the an-
swer type specifies whether the target is one option,
a complete valid set, or a distribution. We measure
input length using the full text seen by the model,
including the state, query, option names, and option
criteria. Each example is capped at 65,535 tokens.
Among the 5,448 examples, 3,155 are shorter than
1K tokens, while 356 exceed 8K tokens, includ-
ing 107 longer than 32K. The number of options
ranges from 2 to 1,024. At inference time, the
actual token usage can be slightly higher because
model providers add their own request formatting
and reserved tokens.
Decision Interfaces.Jev exposes three inter-
faces for different kinds of requests (TypeSafe AI,
2026). They specify what the model returns. The
answer types in Section 3.1 specify what makes a
prediction correct and how it is evaluated.
Choicecompares named options. A support re-
quest might ask whether a ticket belongs to billing,
shipping, or returns, with each option’s criterion
defining its responsibilities. The response contains
the selected option and a probability for every op-
tion. In MMDM, this distribution supports evalua-
tion against a single correct option, a set of equally
valid options, or a soft reference, according to the
task’s answer type.
Noulanswers a yes/no query, such as whether a
message requests a refund. It returns the probabil-
ity of yes; values near one favor yes, values near
zero favor no, and values near one-half express un-
certainty between them. The remaining probability
belongs to no, giving the two-option distribution
used in evaluation. A definite reference answer is
hard single-select, while a reference that quantifies
uncertainty is soft-label.
Scoreevaluates an input against ordered, descrip-
tive rubric levels. For report completeness, these
might range from missing required evidence to
meeting every requirement. The response contains
a probability for each level and their probability-
weighted numeric score. MMDM evaluates both
the level distribution and the expected score. There-
fore, Scoring questions belong to the hard single-
select or soft-label track, depending on whether the
reference identifies one level or a distribution.
B Data Sources and Construction
B.1 Source Collection and Adaptation
Table A2 lists every public source represented in
the release, its contribution, and the decision task
obtained from it. We collect labeled questions, sup-
porting documents, response comparisons, code
and database problems, agent trajectories, and tool
or skill descriptions. Table A3 describes the ques-
tion families that we construct from explicit rules,
state transitions, and outcome mechanisms. For
source-grounded rewrites, the original answer and
its supporting context serve as semantic anchors.
We rewrite the state and query and rephrase or re-
place distractors, preserving the facts and relations
needed to justify the answer. The semantic and
option-quality checks in Appendix B.4 verify that
the revised input supports the reference answer and
that incorrect options remain plausible but invalid.
Knowledge, Language, and Document.Adap-
tations preserve task-relevant evidence and label
semantics within the state–query–options interface.
Knowledge and reading tasks retain the premises
needed to distinguish the answer; multi-hop ques-
tions preserve the documents and links joining
the required evidence. Entailment and moderation
tasks express the source labels as named options
with explicit meanings. Emotion tasks preserve
the source text and the relevant emotion inventory.
Preference tasks retain the compared responses and
the criterion governing the comparison. A prefer-
ence between responses remains a selection label;
numerical annotations are used according to their
original meaning.
Code and Database.Program tasks preserve
executable code and its input or specification.

present applicability and the complete valid set.

2026), retrieval annotations from ToolRet (Shi
et al., 2025), and skill descriptions from Graph

troduce concrete goals and prerequisites grounded
in these descriptions. An additional 31 questions
are built from a collected directory of 10,798 skills
with provenance preserved. For each question, we
review every option for functional overlap and ap-
plicability to the current request; all valid options
are included in the multi-select target. Original
retrieval positives and packaged skills serve as ref-
erence candidates, while the expanded option set is
independently reviewed to determine the labels.
B.2 Original Task Construction
We construct new decision instances by specifying
a mechanism, computing its reference answer, and
rendering its states and conditions as natural lan-
guage. The mechanism determines which details
affect the decision. Distractors implement plausi-
ble mistakes, including an omitted prerequisite, an
expired authorization, a stale artifact, a confused
entity, or a missed exception. The final families
and their validation procedures appear in Table A3.
Interdependent Options and Constrained
Plans.Logic tasks define propositions whose truth
values depend on other propositions. We enumer-
ate satisfying assignments and check them with an
independent truth-table implementation. Single-
select questions ask for the unique complete in-
terpretation; multi-select questions ask for all true
propositions under that interpretation. Global in-
terpretation rules are stated in the state, and inter-
dependent statements appear in option.criteria.
We check entity references, quantifier scope, and
natural-language statements against the formal
propositions. Planning tasks evaluate complete pro-
posed assignments against eligibility, scheduling,

C.2 Protocol and Metrics
Context and Option Handling.For context bud-
get B, service allowance H, and output reserve R,
the adapter preserves the query, all options, and
their criteria. It keeps approximately equal token
spans from the start and end of the state and re-
counts the serialized request against B−H−R .
Truncation preserves Unicode boundaries and in-
serts an omission marker. Runs record the provider
or proxy tokenizer. Fixed-field overflow and
provider rejection count as failures; grouped calls
share the prepared state. All requests follow the
protocol in Section 4.1. A supported catalog is eval-
uated in one call. An independent catalog above the
option cap is reduced recursively, with each call
presenting all options in its group alongside the
same prepared state. The highest-probability op-
tion in each group advances for hard single-select.
For hard multi-select, the evaluator uses N=|G|
both as the evaluation cutoff and as the maximum
number retained from each group; neither N nor
the reference option identities enter model requests.
The metric evaluates complete-set ordering at this
reference cardinality. Option-dependent and distri-
butional tasks retain the complete option set with-
out splitting. If that set exceeds a model’s option
cap, the request is recorded as a capacity failure.
Implementation and Averaging.Hard accura-
cies include all questions and count boundary ties,
failed requests, and missing outputs as incorrect.
The implementation treats probability differences
of at most 10−12 as ties. SB-F, Soft Brier, and
Score nMAE use valid native outputs over the com-
plete option set. Each Score error is normalized by
that item’s rubric range.
