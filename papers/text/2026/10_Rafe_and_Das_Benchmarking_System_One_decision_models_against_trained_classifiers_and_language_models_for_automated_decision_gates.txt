3.2. Harness and experimental protocol
One harness sends every model the same request, which is the TypeSafe wire body of a shared state and a set of
typedquestions.Thehostedmodelreceivestherequestthroughthevendor’ssoftwaredevelopmentkit,andeverylocal
checkpoint receives it through an in-process adapter that implements the same route. Every model therefore receives
the same semantic request, with the same state, question and option texts in the same order. The rendering into tokens
is the model’s own, and one adapter departs from the common option text, since this-that-model-1.0 exposes no field
for an option description and receives each option key joined to its description by a colon (Section 4).
Every returned distribution is normalized into one shape before any metric is computed, so a difference in the
reported numbers reflects a difference between models rather than between parsing paths. Each condition is frozen
once to a JSON Lines file whose SHA-256 digest and random seed, 20260924, are recorded in a manifest, and every
model reads that same file. The frozen files also let an interrupted run resume without repeating work. The harness
never shortens a request, and each model applies its own input limits.
A transient service error is retried a bounded number of times with only the final outcome recorded, and a request
that a model rejects is recorded as a refusal and scored as missing rather than repaired. A generative reply from which
no distribution over the declared options can be read, because it holds no parseable JSON or names no declared key,
is scored as a uniform distribution, so an unreadable reply counts against the model rather than leaving the scored
set. The only refusals in the study are the 800 requests on which Laya (English) found the full intent list longer than
its option budget, and Table C.12 in Appendix C lists the resolved revision, served temperature and runtime of every
model. The study measures the checkpoints available on the run dates in that table, and the released harness accepts
any further model that implements the same request format.
